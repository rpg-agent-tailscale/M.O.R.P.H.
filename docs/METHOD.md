# The MORPH method

1. **Observe**: state the user's real problem and expected measurable outcome. Inventory existing apps, open-source projects, components and local code.
2. **Decide**: score CONFIGURE, EXTEND, FORK/MORPH, RECONSTRUCT, BUILD NEW by time-to-usable-result, licensing, fidelity, complexity, safety, and maintenance. Restrict discovery to a ~30-minute default budget.
3. **Soul**: specify behavior using inputs, outputs, edge cases, and independent acceptance tests. Mark evidence versus hypothesis.
4. **Body**: state the visual contract, approved assets, runtime and invariants that must not change.
5. **Execute**: make the smallest reversible change and run one bounded real proof.
6. **Verify and ship**: measure before/after; require an attributable Checker result. Record nonblocking deficiencies as Improvement Debt.

Default to one functional capability, not multiple micro-missions. Do not promote unverified claims into implementation evidence.
